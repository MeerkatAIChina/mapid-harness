## 2. R3 缺口清单

### 2.0 字数语义修正（2026-10-28 增补裁定，修正 R2 的 C5/P6 设计）

用户对「10 万字」的定调（原话三点）：①10 万字是**级别/检测环境**，不是非要 10 万字；②**绝对不能为了交差而交差**——7 万字写得很好就不必硬凑，如实说明，敢于实事求是；③强调 10 万字是创造检测环境，检验超长输出下暴露的问题（10 万字能做扎实，一般报告卓卓有余）。

设计含义：R2 的 C5「合并前 ≥100,000 硬闸门」与 P7（复制粘贴）是**因果关系**——硬闸门制造字数压力，压力催生行为畸变。R3 修正为「**目标 + 诚实出口**」：保留 10 万字拉伸目标（否则失去检测环境），加厚循环的合规出口扩展为「加深加厚，**或如实声明内容已充分**」（与红线「宁可 [待核实] 不可编造」同构：宁可字数不足，不可复制粘贴）。P7=0 因此成为兜底红线——字数硬线放松后，防凑字数全靠它。验收线 P6 相应改写（见 §4）。

## 3. R3 的核心问题（调研必须回答）

**P1/P2/P3 的共同模式是「全量尺度后半程行为衰减」，且 v4 的章级刚性工序（a~e）没有拦住。** R2 已证明：

1. 提示词层的「规则 + 工序 + 闸门」在任务前半程有效（01~05 章 P1 密度显著低于后半程章节；财务章有真实检索数据支撑时遵守率最高）；
2. 同一套工序在后半程被整体跳过（台账停更是最硬的证据——它不是做不好，是没做）。

R3 必须回答：**剩余的行为缺口，提示词层还能挤出多少，还是应该换层？**

候选方向（调研阶段评估具体方案，**路线已裁定开放机制层，见 §7-1**）：

- **A. 继续提示词层**：节级颗粒化工序（把章级验收 a~e 下沉到节级）；「先搜后写」绑定到每个含数字段落的强制动作；05 章型大章的强制拆分。
- **B. 机制层（检查器前移）**：每章写完由 harness 自动跑 report_qa，把该章 findings 作为反馈注入对话，要求模型自修后才准写下一章——把「完稿后评审」变成「写时反馈」。这是 mapid-harness 层改动（不动 Octop 内核），若采用需记录设计决策。**必须条件（评审裁定）：门禁带自修次数上限**——同章自修 N 次（如 2 次）仍不过 → 放行 + trajectory 记录，留完稿评审；门禁职责是「逼模型自修」，不是「章章完美」，无出口会死循环。
- **C. 混合**：提示词层修「不均匀」（定性章节的来源动作），机制层修「后半程衰减」（外部强制反馈，不靠模型自觉）。

## 7. 裁定点（2026-10-21 评审定稿）

1. **路线开放度 → 开放机制层（方向 B/C）**。理由：①这是 v1.0.3 设计 §3.1 预留路径到期（「先完稿后跑积累数据，再前移为章节级门禁」——触发条件已齐：TP 10/10、FP=0、两轮全量证明后半程衰减真实）；②后半程衰减是长上下文结构性问题，提示词层原理上解不了（依赖模型在 60k+ 上下文后仍自觉），外部强制不随上下文长度衰减；③工程上是小改动（检查器 R1 已按可复用模块建，前移只是换挂载点，不动内核）。**必须条件：门禁带自修次数上限**（同章 N=2 次仍不过 → 放行 + trajectory 记录，留完稿评审）。
2. **打包方式 → 同轮，顺序钉死**：`M1 修正 → 金缺陷回归复跑 + round-3 快照复跑（numeric_consistency = 0）→ 门禁才上线`。理由：门禁若用带误报的检查器，会把正常章打回、逼模型「修复」不存在的问题（把好数据改错）；真实产物分布上 0 误报才算修好。
3. **P7 定线 → 0 线（行为类口径）**。复制粘贴式加厚是行为选择非能力边界（前半程就在写新内容）；检查器可信（round-3 的 3 条命中深审全真、无 FP）；注水有合规出口（加深方向），复制没有借口。
4. **P1 考核口径 → 维持全文 0 线，不设章级线**。数学事实：验收线为 0 时「全文 = 0」与「每章 = 0」等价，章级线是冗余条款；章级颗粒度用在真正有用的地方——门禁机制天然章级 + 验收报告按章分布呈现（供归因）。

**评审补给调研的两个问题（§3 之外，调研必须回答）**：

- **Q-A 门禁前移的检查器范围**：四个检查器全前移（P1/P2/P3/P7），还是只前移 `ledger_freshness` + `degeneration`（衰减最重 + 防死循环最关键——退化章若被字数闸门打回重写，门禁不拦退化会循环复制）？需成本测算：全前移 = 13 章 ×（检查 + 自修）的轮时增幅（本轮纯生成已 68 分钟）。
- **Q-B findings 注入形态**：对话消息注入 vs 工具返回值？findings 用什么格式模型最易执行（行号 + 缺陷类型 + 修法）？决定自修效率与 token 成本。
