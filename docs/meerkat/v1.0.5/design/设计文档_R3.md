## 3. 子包 M：尺子修正（先行，独立验证）

### 3.1 M1：numeric_consistency 分组键修正

- **现状**（`report_qa/checks.py:604`）：分组键 = 「指标名」→ 多年份分行必误报；
- **修正**：分组键 = （指标名， 口径/年份）；同组内才判冲突；
- **粒度兼容规则**：同组两数值规范化后互为子串（「2016 年」⊂「2016 年 6 月」）= 精度差异，不报；
- **实现钉（评审）**：M1 的台账内区间冲突判定**复用 M3 的区间解析器**（共享代码，不是「天然覆盖」——区间解析/重叠判定抽为公共函数，两处调用）；
- **金缺陷 GD-18**（text_injectable）：①同指标多年份分行 → 不报；②同指标同口径两值 → 报；③同口径粒度差异 → 不报。**GD-18/19/20 各管各的能力，验收分开判（立项合并 ≠ 验收合并）**。

### 3.2 M3：conclusion_source 检查器（新增，内含 M2 区间比对）

- **职责**：扫结论章（12 章）的「数字 +（见第 X 章）」出处锚点 → 到第 X 章文本检索该数值 → 未找到/区间不重叠 = findings。E1（跨章抄错）与 E9（区间相邻不重叠）两型都由它抓；
- **区间判定**：[a,b] vs [c,d]，b < c − ε 或 d < a − ε（ε = 0.1pp）→ 矛盾；边界相接（8–12% vs 12–14%）判矛盾（E9 正是此型）；一处为点值时按退化区间处理；
- **金缺陷 GD-19**：结论章出处锚点数字被篡改（前文 39.16% 结论章写 36.91%）→ 应报；**GD-20**：区间相邻不重叠 → 应报，重叠 → 不报；
- M2（区间一致性）不单独立项：其跨章判定依赖出处锚点，M3 的区间比对逻辑即 M2 的可落地形态。台账内区间冲突由 M1 修正后的分组键覆盖（同口径不同区间 = 冲突，复用 M3 区间解析器，见 §3.1）；
- **已知盲区（评审声明，记档）**：M3 只扫结论章引用、M1 只看台账——**未进台账的正文与正文之间的区间冲突**（E9 原型：03 章 vs 09 章净利率）两者都不覆盖，目前靠 Claude 深审兜底。round-4 若再犯此型，再立项全文区间扫描。

### 3.3 M 包验证（先于 G 上线，裁定顺序）

金缺陷回归（TP 全绿 + FP=0）→ **round-3 快照复跑：numeric_consistency = 0 且 conclusion_source 对 round-3 快照无 FP**（round-3 结论章数字已与前文一致——深审实证过，可作为「正确产物」负样本）。

## 4. 子包 G：章节门禁（机制层，零内核）

### 4.1 形态：ChapterGateMiddleware（新中间件）

- **挂载**：`octop_harness/agent.py` 既有 config-flag 模式，新增 `chapter_gate_enabled`（默认关，经 agent config 或 env 开启）；`wrap_tool_call/awrap_tool_call` 拦截，模式同 `FilesystemGuardMiddleware`；
- **评估器**：复用 report_qa 现有检查函数（跑 workspace 后按 `file` 过滤本章），零重构；单章评估 < 1s，无感。

### 4.2 状态机（两个触点）

```
report_stats(chapters/NN.md)   ← 模型自认本章写完（v4 工序 a，实测全程无衰减）
  → 跑章级检查（P1/P2/P3/P7 四检查器，过滤本章）
  → findings 以附言追加进 ToolMessage（工具返回值注入，见 §4.3）
  → 更新门禁状态：NN = clean / dirty(findings)

write_file / edit_file(chapters/MM.md)   ← 开写新章（MM 未写过）
  → 若存在脏章 NN 且 NN.repair_rounds < 2：
      阻断，返回 ToolMessage(status=error)：
      「门禁：第 NN 章有未修复问题（k 条），先修复再继续。详情见上次 report_stats 附言」
      NN.repair_rounds += 1
  → 若 NN.repair_rounds ≥ 2：放行 + logger.warning（trajectory 可考）+ 附言「已达自修上限，记录放行」
  （对已有章节的 write/edit 不阻断——修旧章永远允许；
    progress/ledger/outline 等非章节文件永远不拦）

merge_chapters                 ← 最终闸门
  → 全量检查（四检查器 + numeric_consistency(M1 后) + structure）
  → findings > 0 且 merge_rounds < 2 → ToolMessage(status=error) + findings 摘要
  → merge_rounds ≥ 2 → 放行 + logger.warning
  **（评审钉：merge 闸放行的 findings 必须显式写进验证轮验收记录并逐条清点——
  「放行」≠「门禁通过」，判死刑的是量化线，门禁只负责制造修复机会）**
```

**实现钉（评审 2026-10-29）**：

1. **拦截面覆盖 edit_file**：round-3 实测 edit_file ×48 > write_file ×24（模型改内容主要走 edit_file）；「write 骨架 + edit 填充」的开新章路径必须同样被拦——拦截条件 = 两个写工具 × 目标路径为**尚不存在的** chapters/*.md 新文件（edit_file 对不存在文件报错本就失败，但 write 骨架后首次 edit 填充要视为开新章延续：以「该文件首次出现内容写入」判定，同一脏章窗口内的骨架+填充视为同一次开章）；
2. **execute 绕路洞**：被挡急了模型可能用 shell 写文件。通用拦截成本高，务实处理 = v5 门禁锚定条款加「禁止用脚本/execute 绕过内建工具写章节文件」+ round-4 trajectory 专项盯 execute 调用（见 §6）；
3. **状态机闭环确认**：dirty → 修改置 unevaluated → 复测刷新 → 放行；N=2 按拦截次数计；非章节文件永远不拦、修改脏章本身（修复路径）永远不拦——实现时不得弄丢。

设计要点：

1. **硬门禁（写新章阻断）而非纯提醒**——调研 §2.4 的分级在硬门禁形态下简化：四类检查器全部纳入阻断，因为 0 线均可经合规出口达到（无来源 → 标 [待核实]；缺题注 → 补两行；台账漏登 → 补登记；退化 → 重写）。**合规出口的存在使硬阻断无死锁**，N=2 上限是最后保险；
2. **自修上限 N=2**（评审裁定必须条件）：按章计数，上限后放行 + trajectory 记录，留完稿评审；
3. **report_stats 附言始终注入**（即使不阻断）——它是模型的决策窗口；
4. **dirty 状态在旧章被修改后自动失效**（write/edit 到 NN → NN 置 unevaluated，下次 report_stats(NN) 重新评估）——鼓励修复后主动复测；
5. **门禁不猜意图**：只认两个工具触点的确定信号，不解析正文。

### 4.3 附言格式（Q-B）

追加在 report_stats ToolMessage 末尾，纯文本，每条一行：

```
[chapter_gate] 本章检查发现 3 项：
- 行 187：无来源精确数值（25,000, 30,000…）→ 补来源标注或标 [待核实]
- 行 224：完全相同行重复 4 次 → 重写重复段，禁止复制凑字数
- 台账：本章含精确数值但无「首现章节=06」条目 → 先登记 data_ledger.md
修复后请再次调用 report_stats 复测。
```

### 4.4 dry-run 验证（上线前）

门禁逻辑离线跑 round-3 快照：以 trajectory 中各章 report_stats 调用时点为序，回放「若门禁在线，每次附言/阻断内容是什么」，人工核对无误伤（重点是：01–05 章前半程不应被误阻；06 章起应阻断且附言正确）。dry-run 报告入 round-4 检查单。

## 5. 子包 v5：提示词微调（最小增量，防稀释）

v4 → v5 变更仅四条：

1. **C5 软化（§2.0 字数语义修正）**：合并闸门条款改为——「合并前 report_stats 总量目标 ≥100,000；**若内容已充分而不足 100,000，在 progress.md 与结论章如实说明实际字数与理由，禁止以任何形式凑字数**（宁可不足，不可复制）。」outline 章级下限分配保留（拉伸环境不变），加厚循环条款保留「加深方向」清单；
2. **雷同值禁令**（打调研 §1.1 新发现）：「对比表格中不同主体的同一参数**禁止整行/整列雷同值**（如四家寿命同为 25,000/30,000/50,000 小时）——出现雷同即视为凭印象填数，必须检索差异化数据或逐格标 [待核实]」；
3. **大章拆分**：单章下限不得超过 12,000 字（v4 已有 6,000–12,000 区间，round-3 的 05 章分配 20,000 自我违反）；竞品逐家章超限必须拆为两章（各 ≤5 家）；
4. **门禁锚定**：「report_stats 返回中如出现 [chapter_gate] 段落，必须逐条处理完再继续；被门禁阻断时，先修复所指章节再继续。**禁止使用脚本或 execute 工具绕过内建工具写章节文件**——章节文件一律经 write_file/edit_file 写入。」

**评审附注（2026-10-29）**：大章拆分改变章节结构后，P2「05 章独占 16 条」的按章基线对比失真——round-4 验收对比一律改用**全文密度**，不按章。

其余 v4 条款一律不动（P4/P6 已验证有效）。

## 6. 验证设计

1. M 包：§3.3 顺序验证（金缺陷回归 + round-3 快照复跑双 0）；
2. G 包：TDD（中间件单测：阻断/放行/上限/附言格式/状态失效）+ dry-run（§4.4）；
3. round-4 验证全量轮：同任务同 agent，v5 + 门禁开（`chapter_gate_enabled`）；轮次准备检查单照旧（记忆/workspace 隔离）；**round-4 开跑前先做 PYTHONUTF8 最小触发测试**（两分钟：任一 grep 调用不炸即实证，不拿 160 分钟的轮去赌）；
4. 判定：§2 量化线；trajectory 加采「附言注入响应率」「阻断次数/放行次数」；
5. **round-4 trajectory 专项盯四个信号（评审钉）**：①拦截/放行次数分布；②绕路尝试（execute/edit_file 异常用途）；③report_stats 调用数（防模型为躲门禁不调）；④N=2 触发率。**dry-run 测不了模型对硬门禁的行为反应**（绕路/死磕/躲门禁）——此残余风险由 round-4 直接承担；若因此翻车，归因机制层（改门禁）而非行为层失败，重跑成本一轮，可接受；
5. 副作用监控：门禁是否引发新型畸变（如模型为避免阻断而不调 report_stats——若发生，字数工序也丢失，检查器层 P6/台账会暴露）。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 门禁误判伤正常章 | M 包先行钉死顺序；dry-run 用 round-3 快照（真实分布）验证 |
| 硬阻断死循环 | 合规出口可达 0 线 + N=2 上限放行 + merge 闸同上限 |
| 模型为躲门禁不调 report_stats | P6/字数工序丢失会被检查器与验收线暴露；v5 门禁锚定条款明示；trajectory 监控 report_stats 调用数 |
| v5 + 门禁同轮归因模糊 | 缺口分工明确（§1 归因规则）；验收报告按章分布拆解 |
| 轮时膨胀 | 自修轮次估 +10~20 分钟；超时预算 130 → 160 分钟 |

## 8. 评审裁定记录（2026-10-29，四确认点全部认可）

1. **硬门禁 → 认可（评审升级立场）**：误伤（M 先行 + dry-run 真实分布回放）、死循环（合规出口 + N=2）、响应率未知（硬门禁不依赖模型服从）三风险全堵死；核心论证——文字提醒会衰减，工具错误是机械事实，结构性免疫于上下文衰减。附三个实现钉子 → 已落 §4.2（edit_file 拦截面 / execute 绕路洞 / 状态机闭环确认）。
2. **M2 收敛进 M3 → 认可，附盲区声明**：M1 复用 M3 区间解析器（共享代码）；GD-18/19/20 验收分开判；正文-正文区间冲突盲区记档（深审兜底，round-4 再犯则立项全文扫描）→ 已落 §3.1/§3.2。
3. **merge 闸 N=2 放行 → 认可**：门禁职责是制造修复机会不是当验收法官（放行的 findings 交完稿评审清点，验收照样判）；永不放行 = 挂死等人工救，破 0 干预线本末倒置。钉：放行 findings 逐条写入验收记录 → 已落 §4.2。
4. **dry-run 替代试点轮 → 认可**：快速轮只有前半程、门禁主战场在后半程，试点轮信息量低；残余风险（模型对硬门禁的行为反应）归 round-4 承担，翻车归因机制层 → 已落 §6。

**评审顺带两点**：①诚实出口使用率观察指标 → 已落 §2 P6 行；②大章拆分致按章基线失真，验收对比改全文密度 → 已落 §5；③PYTHONUTF8 开跑前最小触发测试 → 已落 §6。
