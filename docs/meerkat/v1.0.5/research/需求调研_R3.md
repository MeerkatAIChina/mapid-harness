# 需求调研：调优 Loop R3

> 版本：v1.0.5 · 2026-10-21 · 状态：定稿
> 依据：[需求描述_R3](../requirement/需求描述_R3.md)（已定稿，含四点裁定与评审补充问题 Q-A/Q-B）
> 数据源：`v1.0.4/rounds/round-3/`（验收记录 + 深审报告 + findings + 产物快照）、mapid-harness 源码实读

## 0. 结论摘要

1. **路线建议：C 混合**——机制层「章节门禁」为主（打 P3/P7 + 后半程衰减），v5 提示词微调为辅（打 P1/P2 的章节不均匀）。纯提示词层（A）已被 R2 证伪于后半程；纯机制层（B）对「定性章节凭印象填数」不对症。
2. **挂载点已实证可行，零内核改动**：langchain `wrap_tool_call` 有既有先例（`FilesystemGuardMiddleware`），门禁挂在 `report_stats`（章验收触点，round-3 实测模型每章必调 ×43）+ `merge_chapters`（最终兜底）两个工具调用上；中间件经 `octop_harness/agent.py` 既有 config-flag 模式挂载。
3. **M1 修正方案明确**（分组键补「口径/年份」列 + 粒度兼容规则），可先行独立验证（金缺陷回归 + round-3 快照复跑）。
4. **无阻塞项**，可进设计。

## 1. P1/P2/P3 残留归因验证

### 1.1 抽验：P1 残留是真缺口，且暴露了更糟的行为

06 章 P1 抽验 3 条（findings L187–189），全部属实，且发现新行为模式：

> L70（光源寿命）对比表中，欧普/雷士/佛山/三雄**四家数值完全相同**（25,000/30,000/50,000 小时），无来源、无 [待核实]。

这不是「忘了标来源」，是**凭印象填数且填成均匀值**——红线「禁止凭印象填数」在定性/参数类章节的直接违反。财务章（03/09）P1 密度低的原因随之清晰：那里有 StockAnalysis 真实检索数据撑着；**没有检索数据的章节，模型选择编整齐的数字填满表格**。v4「搜不到就标 [待核实]」的出口在这些章节被无视。

**归因结论**：P1/P2 残留 ≠ 规则不清，= 定性章节「先搜后写/无源即标」动作未发生。提示词层已在 R2 把规则写到段落级仍不够 → 需要外部强制反馈（门禁）+ v5 针对性条款（表格内禁止整行/整列雷同值）。

### 1.2 P3 台账停更的精确时点

台账最后写入 10:57（05 章完成时点）；checker 判定 01/06/07/08/09/10/11/12 章无「首现章节」条目（02–05、13 有）。即 C4「登记完才准写下一章」在**第 6 章起被整体放弃**——与 outline/进度维护正常并行，唯独台账工序丢失。佐证「后半程衰减」的选择性：越繁琐、越无即时回报的工序越先被丢弃。

## 2. 机制层方案可行性（评审问题 Q-B + 挂载点）

### 2.1 挂载点：wrap_tool_call 有既有先例，零内核

- langchain agents middleware 提供 `wrap_tool_call / awrap_tool_call(request, handler)`：可检查工具名与参数、放行执行、**改写返回的 ToolMessage**（`middleware/filesystem_guard.py` 既有模式，拦截路径参数 + 软化异常为 ToolMessage）；
- 新中间件挂载点 = `octop_harness/agent.py` 既有 config-flag 模式（`cfg.tool_guard_enabled`/`pii_enabled` 同款），mapid-harness 自有文件，两个 repo 内核零改动；
- report_qa 检查器**无需重构**：现有函数跑 workspace 后按 `file` 字段过滤本章 findings 即可（正则级计算，单章毫秒级）。

### 2.2 触点选择：挂在模型已经在做的动作上

| 触点 | 性质 | round-3 实测 |
|---|---|---|
| `report_stats(chapters/NN.md)` | **章验收时刻**（v4 工序 a，模型自认本章写完） | ×43，每章必调，后半程也在调（11 章 4,020 字也走了实测） |
| `merge_chapters` | 最终闸门（合并前全量检查兜底） | ×1 |

关键洞察：**字数闸门没有衰减**（report_stats 全程 ×43，含 11–13 章），衰减的是台账/来源/题注工序。把门禁挂在 report_stats 上 = 把「模型已保持的行为」升级为「其他工序的强制触发点」，不依赖任何新习惯的养成。这是本调研最重要的设计依据。

### 2.3 findings 注入形态（Q-B）

- **形态：工具返回值附言**（append 到 report_stats 的 ToolMessage content），不另发对话消息。理由：模型此刻正拿着统计结果做「达标/加厚」决策，反馈在同一上下文位置、同一决策窗口内；对话消息注入会打断工具链、且与 turn 边界耦合。
- **格式（每行一条）**：`[chapter_gate] 本章检查发现 N 项：行 187 无来源精确数值（25,000/30,000…）→ 补来源或标 [待核实]；行 31 段落逐字重复 → 重写该段…`。要素 = 行号 + 缺陷类型 + 一句修法，与 findings JSON 的 `line`/`message`/`evidence` 字段直接映射。
- **自修计数（裁定必须条件）**：中间件实例状态 `dict[chapter_file, flag_count]`；同章第 N=2 次仍有 findings → 附言改为「已达自修上限，记录并放行」+ `logger.warning`（trajectory 可考），不再要求自修。

### 2.4 门禁范围（Q-A）：成本测算与建议

检查器按作用域分两类：

| 检查器 | 作用域 | 章门禁 | merge 闸门 |
|---|---|---|---|
| unsourced_precise（P1） | 章级 | ✅ | ✅ |
| figure_companion（P2） | 章级 | ✅ | ✅ |
| ledger_freshness（P3） | 章级归因（需读台账） | ✅ | ✅ |
| degeneration（P7） | 章级 | ✅ | ✅ |
| numeric_consistency | 台账级 | — | ✅（M1 修正后） |
| structure | 跨章级 | — | ✅ |

- **计算成本可忽略**（正则级，全 workspace 一遍 < 1s）；
- **真实成本 = 自修轮次**：每轮自修 ≈ 1 个模型回合（30–60s）。按 round-3 分布估算（后半程 ~8 章有 findings，均 1–2 轮）→ **轮时 +10~20 分钟**（基线纯生成 68 分钟，增幅 15–30%）。可接受。
- **建议（待设计定夺）**：章门禁四个检查器全前移、**但分级处理**——`degeneration` + `ledger_freshness` 为**阻断型**（计入自修上限，防复制粘贴循环与台账停更）；`unsourced_precise` + `figure_companion` 为**提醒型**（注入 findings 但不计自修上限、不阻断进度）——理由：P1 残留 73 条的量级若全阻断，自修轮次不可控（模型修 unsourced 需要检索，一轮修不完）；提醒型注入仍能给完稿评审前的「边写边修」创造机会。此分级是设计文档的首要裁量点。

## 3. M1 修正方案（numeric_consistency 口径）

- **现状**（`report_qa/checks.py:604`）：分组键 = 「指标名」单列，同指标多年份分行必误报（round-3 的 14 条全属此类）；
- **修正**：分组键 = （指标名， 口径/年份）；同组内不同数值才报冲突；
- **粒度兼容规则**：同组内两数值互为子串（如「2016 年」vs「2016 年 6 月」）= 精度差异非冲突，不报——否则 round-3 快照的「上市时间」重复行会残留 1 条（该行本身是台账卫生问题，由 ledger_freshness/深审覆盖，不归 GD-07）；
- **验证（裁定顺序）**：先补金缺陷样本（GD-18：多年份分行不报 + 同口径两值应报 + 粒度差异不报）→ 金缺陷回归 TP/FP 全绿 → **round-3 快照复跑 numeric_consistency = 0** → 门禁才允许上线；
- 同步补 R2 挂账 M2/M3 的评估：M2（区间一致性）建议与 M1 同批做（同为 numeric 族尺子）；M3（「（见第 X 章）」钩子）工作量小可顺手，均记设计文档。

## 4. v5 提示词微调方向（辅包，配合门禁）

1. **针对 §1.1 新行为**：表格单元格禁止整行/整列雷同值（「不同主体的同一参数若完全相同，视为凭印象填数，必须检索或标 [待核实]」）；
2. **针对 P2 的 05 章集中**（16/28）：大章（>15,000 字）强制拆分为两家竞品一写，降低单章工序负担；
3. **门禁协作条款**：明示「report_stats 返回中如出现 [chapter_gate] 检查结果，必须先处理再继续」——门禁生效不需要模型「新习惯」，但需要一句「附言是命令」的锚定；
4. 其余 v4 条款不动（P4/P6 已验证有效，防稀释）。

## 5. 风险与开放问题

| 风险 | 对策 |
|---|---|
| 提醒型注入被模型无视（回到行为衰减） | 完稿评审兜底不变；merge 闸门全量检查为最后防线；R3 验证轮实测注入响应率（trajectory 可统计：附言后下一动作是否为修复） |
| 门禁误判打断正常流程 | M1 先行 + 裁定顺序钉死；章门禁上线前以 round-3 快照做干跑（dry-run）验证 |
| 自修轮次膨胀轮时 | 自修上限 N=2 + 分级（§2.4）；超时预算从 130 分钟上调至 160 分钟 |
| v5 条款与门禁职责重叠致指令稀释 | v5 只写门禁做不到的（雷同值禁令、大章拆分），门禁能强制的不写第二遍 |

## 6. 调研结论

路线、挂载点、成本、M1 方案均已落实，无阻塞。**建议进设计文档**，首要裁量点：门禁分级（阻断型 vs 提醒型的检查器划分）。
