## 工作量与风险预算

- 阶段 M：**~1 天**（评审微调：区间解析器的格式边角 + 两条检查器改动 + 三条金缺陷 + 双回归，半天偏紧）；阶段 G：~半天（中间件 + dry-run）；V1：~0.5h；R 阶段：一轮全量（生成 ~70–90 分钟 + 验收 ~1h）；
- 风险预算：round-4 若因门禁行为反应翻车（绕路/死磕/躲门禁），归因机制层，重跑一轮；
- 超时预算：130 → 160 分钟。

## 提交策略（沿用惯例，每批需用户批准）

1. 阶段 M 完成：`feat(report_qa)` + `feat(golden_defects)` + 回归记录；
2. 阶段 G 完成：`feat(middleware)`；
3. V1：`docs(meerkat)` v5；
4. round-4 验收后：`docs(meerkat)` 验收批次 + R3 文档批次（需求/调研/设计/本计划可提前随 M 或 G 批提交）。
