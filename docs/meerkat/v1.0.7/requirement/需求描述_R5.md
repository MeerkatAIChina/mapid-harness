# 需求描述_R5：merge 自洽与核验降噪

> 版本：v1.0.7 · 起草 2026-11-09（需求梳理稿，待评审）
> 前置：R8 验收记录与观察记录（`v1.0.6/rounds/round-8/`）；
> 对标素材：Kimi 单会话版欧普报告（`rounds/round-8/` 复盘对比节，原文件 `E:\kimi-desktop\kimi\Workspaces\论文\欧普照明竞品分析深度报告_完整版.html`）

## 1. 背景

R8 拆分判定：**写作链路与交付链路通过，merge 自洽不通过**。机制首次产出完整 10 万字级报告
（117,079 非空白字符，15 章，三格式齐备），但 merge 段三道工序（审校/补核/硬闸）互相重置
构成死锁，出口条件不可达，最终靠人工停机手术放行。同时核验层噪声过大：53% 断言判
「无法证实」，其中相当部分是 judge 检索未命中误伤已带编号来源的合法数据。

R5 两条主线：**merge 自洽**（消灭死锁，让合并段无需人工干预）+ **核验降噪**（压误报、
提缓存命中、回收 [待核实] 口径）。辅线：表达锋利度（吸收对标报告的咨询框架）。

## 2. 需求清单

### A. merge 自洽（P0，死锁三件套）

| # | 需求 | 出处 |
|---|---|---|
| A1 | **审校收敛上限**：每章自动审校 ≤N 轮（建议 3），之后只标记不再改文。审校是润色工序，真实性由核验兜底，截断代价可控 | R8 实证：审校 281 次动作、从不零改动，是死锁第一动力源（观察记录 §7） |
| A2 | **编辑清零区分通道**：`chapter_gate.py:1129` 的「编辑即清零」需区分 agent 工具写入与人工/外部修改；或提供 merge 前「冻结章节」模式，冻结期内编辑不重置门禁状态 | R8 实证：人工止损两次被 agent 微调反噬（06/15/03 章各一句话触发整章清零） |
| A3 | **增量重核**：断言绑定正文行号区间/段落指纹，编辑只重核受影响断言，不再整章重抽重核 | R8 实证：整章重核 × 抽取漂移双重放大，每次重核冒出新疑点（观察记录 §7） |

### B. 核验降噪（P1）

| # | 需求 | 出处 |
|---|---|---|
| B1 | **断言规范化缓存键**：缓存键对齐事实（实体+数值+口径）而非措辞 | R8 实测缓存命中 47%，大量同事实异措辞重复核验 |
| B2 | **[待核实] 口径回收**：以 ADR-002 修复后的核验层回测 R8 合并稿，输出「172 处应降到多少」的量化报告；误标集中模式入金缺陷清单 | R8 遗留指标（验收记录 §6） |
| B3 | **judge 误判治理**：证伪张冠李戴（Hue/Matter 案：证据页说的是别家产品）模式化，judge 提示词加「证据主体一致性」自检 | R8 观察记录 |

### C. 流程体验（P2）

| # | 需求 | 出处 |
|---|---|---|
| C1 | **merge 问题一次报全**：`_evaluate_all` 不再「修 1 项冒 1 项」，首轮即输出全部阻断项 | R8 实证：同号异源逐项挤牙膏，多花两轮人工往返 |
| C2 | **同号异源归一化**：比对时剥离括号内注释性后缀，只比书名号内来源标题 | R8 实证：[36] 案——同一来源两种注释被判异源 |

### D. 表达锋利度（P2，辅线，可选立项）

| # | 需求 | 出处 |
|---|---|---|
| D1 | **写作规约吸收咨询框架**：情景模拟（价格战三情景）、红队风险登记册、敏感性分析进提示词模板 | 对标：Kimi 单会话版报告（复盘对比节） |
| D2 | **估计分级声明**：正文数值区分「事实/估计/判断」三级并在文末给使用边界声明 | 同上；与现有 [待核实] 体系需对齐口径，见 §3 |
| D3 | **图表表现力**：mermaid/语义图在 docx/PDF 中退化为代码块的问题需解决（转图片或转表格） | R8 已知限制（交付说明 §4） |

## 3. 冲突预警与改造点（设计阶段必须解决）

| 冲突 | 说明 | 改造方向 |
|---|---|---|
| **A2 冻结模式 vs 状态机语义** | 「编辑即清零」是真实性的最后防线，松开即开造假后门 | 冻结只豁免「merge 前检查器触发的微调」或「非 agent 通道写入」；豁免事件必须落盘审计（写 gate_release_notes 类记录） |
| **A1 审校上限 vs 审校价值** | 审校确实抓到过作者看不出的错（R8 前 4 轮各改 26–60 处） | 上限后未处理的审校意见不丢弃，汇入报告附录「审校保留意见」，把裁量交给人 |
| **D2 估计分级 vs [待核实]** | 两套标记语义重叠：「估计」是有依据的推算，「待核实」是检索未命中 | 设计阶段统一标记体系：事实[ref] / 估计（含依据）/ 判断 / 待核实，四态互斥 |
| **A3 段落指纹 vs 台账凭证** | ADR-002 后台账编号本身是结案凭证，指纹绑定不能破坏该语义 | 指纹只管「重核范围」，结案判定仍走 ADR-002 通道 |

## 4. 验收线草案（评审前初拟）

- **核心线：R9 验证轮 merge 段零人工干预走通**——从最后一章写完到三格式产出，无停机、无人工改文、无人工改 gate_state；
- 审校轮次封顶生效（无单章超 N 轮）；审校引入新伤（重复段落等）= 0（检查器回归）；
- 核验缓存命中率 ≥ 70%（本轮 47%）；[待核实] 回测报告产出，误标率可量化；
- 金缺陷回归全绿不退步；A/B/C 各项改动须有对应测试；
- 过程线重估：merge 段预算从「不计」改为「≤60 分钟含审校」，全程预算待 R9 实测后重定。
