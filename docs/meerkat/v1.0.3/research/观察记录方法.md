# 观察记录方法：Agent 执行过程的可观测性实践

> 版本：v1.0.3 · 2026-10-19 · 基线任务（欧普照明 10 万字报告）中验证有效的方法，作为后续每轮调优实验的标准观察流程。

## 三条观察线

### 1. Workspace 文件巡检（最直接）

- 路径：`E:\projects\meerkatai-octop\.octop-dev\agents\<AgentId>\`
- 看 `outline.md` / `chapters/` / `progress.md` / `data_ledger.md` 的大小与修改时间，即知进度与节奏。
- PowerShell 读中文文件：`[Console]::OutputEncoding=[Text.Encoding]::UTF8; Get-Content <f> -Encoding UTF8`。

### 2. Trajectory 事件流（工作链还原）

- 数据库：`E:\projects\meerkatai-octop\.octop-dev\octop.db`，表 `trajectory_events`。
- 字段：`agent_id / thread_id / seq / ts / kind(user|assistant|tool|context|compacted|system) / is_error / summary / payload_json`。
- 每轮 LLM 输出（含 tool_call）与工具结果都有记录，`payload_json` 含 `llm_duration_ms` / `tool_duration_ms`；assistant 消息的完整文本在 payload 里。
- 只读查询脚本参考：本机 `%TEMP%\check_dev_activity.py` / `check_event_payload.py`（注意 `python -I` 会忽略 PYTHONIOENCODING，脚本内需 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`）。
- Dashboard 前端也有轨迹面板可直接看。

### 3. 日志

- `E:\projects\meerkatai-octop\.octop-dev\logs\`（注意不是 `~/.octop/logs`——本地开发后端 OCTOP_HOME 是项目内 `.octop-dev`）。
