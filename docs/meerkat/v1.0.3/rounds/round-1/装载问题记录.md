## [2026-10-20] 中间件撞名（已修复）

## 现象

R1 插件装载后（meerkat-resilience 等三个插件启用），所有专家无法启动。接口：

```
GET /api/agents/AD4B6B/status
{"state": "failed", "last_error": "Please remove duplicate middleware instances.", ...}
```

## 定位结论

langchain v1 `create_agent`（`langchain/agents/factory.py:1108`）按 `middleware.name`（= 类名，`AgentMiddleware.name` 返回 `self.__class__.__name__`）对中间件链去重，同名实例直接 `AssertionError`。

中间件链实际顺序（octop `infra/agents/manager.py`）：

```
[Octop ModelRetryMiddleware(最外层, 3796-3804 行 prepend),
 *plugin_middleware(3602 行, 含 PatientModelRetry), TokenQuota, ..., OctopUiOffload]
```

`meerkat-resilience` 插件注入的内层耐心重试直接用了 `ModelRetryMiddleware` 类，与 Octop 外层自装的 `ModelRetryMiddleware` **类名相同** → 撞名。插件默认全局启用，因此所有 agent（不止实验 agent）全部启动失败。

嵌套顺序本身符合 T4 设计（Octop 外层 2 次小退避 + 插件内层 5 次大退避），唯一缺陷是命名。

## 修复

`octop_harness/middleware/patient_retry.py`：新增空子类 `PatientModelRetryMiddleware(ModelRetryMiddleware)`，`build_patient_model_retry` 返回子类实例，`name` 变为 `PatientModelRetryMiddleware`，与外层区分。

新增防回归测试 `test_name_distinct_from_octop_outer_retry`（构造 [外层, 内层] 链断言 name 去重通过）。
