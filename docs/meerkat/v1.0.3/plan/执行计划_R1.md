### T4 断流自动续跑

- **现状**：harness 已有 model_retry middleware（`config/__init__.py:664-668`：`model_retry_max_retries=2`，退避 1s→60s）；基线那次是重试耗尽后抛给前端，人工「继续」恢复。
- **执行方式（go/no-go 决策点，锁住工作量上限）**：先花半天调研 stream_error 抛出链路 → **go/no-go**：改动面可控就走 harness 内核实现自动续跑；不可控则果断降级，不在内核里钻深。
- **内容**：
  1. 参数暴露与调大（如 max_retries 5、退避上限加大），确认 Octop 侧可配置；
  2. **首选**（go）：重试耗尽后自动从 checkpointer 状态续跑（而非终止 turn 等人工）；
  3. **降级**（no-go）：R1 只调大重试参数 + Octop host 层自动重发「继续」，且降级必须带 3 个约束：
     - **重发打标**：trajectory 里不能以 `kind=user` 记录，要标 `system` 或加 `source` 字段——否则污染工作链观察（分不清模型自主行为），收敛条件 5 的「0 人工干预」也无法验证；
     - **循环保护**：连续 3 次重发仍断流 → 停止重发、真正上报，防死循环空烧；
     - **节奏协调**：重发带退避，且 harness 重试参数与 host 重发之间协调好，避免两层重试叠加成重试风暴；
  4. 超出最终阈值的仍上报，但记录清晰错误。
- **验收**：收敛条件 5 的对应项——模拟模型服务断流（本地 mock 或拔测），turn 能无人干预恢复；降级方案下 trajectory 中重发消息有明确标记。

#### T4 决策记录（2026-10-19，调研后定）

**调研结论**：断流不是图崩溃——Octop 自装的 `ModelRetryMiddleware`（max_retries=2，退避 1s→2s）耗尽后 `on_failure` 返回字符串 → 变成无工具调用的 AIMessage → turn **优雅终止**，checkpointer 状态干净；前端把带 `MODEL_RETRY_FAILURE_MARK` 的消息显示为 `stream_error / source: model_retry`；人工「继续」= 开新 turn。原计划 go 方案（checkpointer 恢复续跑）无必要——状态从未损坏。

**决策：Go，走「耐心重试插件」**（比原 go 方案更轻）：

- hook 插件 `meerkat-resilience`（`.octop-dev/plugins/`，环境目录）注入**内层** `ModelRetryMiddleware`（默认 5 次、15s→120s 指数退避，单周期约 4 分钟）；短暂断流在 turn 内吸收，turn 不结束。实现在 mapid-harness `src/octop_harness/middleware/patient_retry.py`，**两个 repo 内核零改动**。
- 实现约束（用户定）：
  1. **参数可配置**：插件目录 `config.json` 覆盖默认值（键 = `PatientRetrySettings` 字段），校准参数不改代码；
  2. **重试可见**：每次失败经 `retry_on` 钩子写 warning 日志（harness 日志带 agent 标签），供观察链路区分机器恢复与人工干预、支撑收敛条件 5 的证据；
  3. **验收对齐**：模拟断流（mock 前 N 次失败）→ turn 内自动恢复、无人干预 → 写进 `rounds/round-1/` 存档。
- 节奏协调：内层单周期 ~4 分钟；外层 Octop middleware 最多再叠加 2 个周期，总耐心约 12 分钟封顶，指数退避不构成重试风暴；循环保护 = 次数硬上限（内 5+1 × 外 3 = 18 次封顶），耗尽后仍走既有 AIMessage 报错。

**Option 2（host 自动重发「继续」）挂为证据触发的候补，R1~Rn 默认不做**：

> 若调优过程中发生 ≥1 次超过重试预算的宕机且导致整轮作废 → 立项 host 重发（带打标/循环保护/节奏协调三约束）；否则 R1~Rn 全程不做。

理由：长宕机是未观测到的假设性风险，基线唯一一次断流是瞬时的；万一发生，代价 = 该轮作废重跑（约 2 小时），不污染收敛判定。先用重试插件跑 R2/R3 收集断流频率/时长分布，有据再立项。

#### T5 实现记录（2026-10-19）

1. **日期注入**：调研确认 harness 系统提示不含运行时日期（仅有 `current_time` 工具，模型不主动调就会写错）。实现为 `src/octop_harness/middleware/date_injection.py`（每次模型调用前把 `当前日期：YYYY-MM-DD 周X` 幂等注入 system message），经 hook 插件 `meerkat-date` 挂载，内核零改动。单测 6/6。
2. **记忆隔离**：调研确认 octop-memory 状态 = 单文件 `agents/<id>/.octop/memory.sqlite`（基线 agent 已膨胀至 536MB，即污染源）。隔离方式 = 归档该文件（harness 下次启动自动重建空库），脚本 `scripts/reset_agent_memory.py`（默认归档可回滚，`--delete` 直删，wal 非空时警告）。比 API 级清理（`Memory.delete_thread` 等）更彻底——API 需枚举全部表，有漏清风险。
3. 准备检查单模板：`plan/轮次准备检查单.md`（每轮复制到 `rounds/round-N/` 打勾存档）。

## 4. R1 整体验收标准

1. 检查器对金缺陷宿主检出率 ≥90%、干净宿主零误报（T1）；
2. 评审链三层回归检出率统计产出，记录于 `rounds/round-1/`（为 Claude 深审 ≥90% 的采信线立据）；
3. 快速轮（5 章缩量）全程 0 人工干预跑通（T4 生效）；
4. 快速轮产物：日期正确、台账结构化、合并走内建工具（T3/T5 生效）；
5. 存档齐全：`rounds/round-1/`（changes.md、提示词 v3、Harness commit、评审结果）。
