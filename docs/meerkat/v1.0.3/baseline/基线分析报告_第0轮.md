## 3. 产物审计结果（两个独立审计，2026-10-19）

### 3.1 事实性与红线审计（含 WebSearch 核查 7 组硬数据）—— 风险等级：中

**好的方面**：上市公司财报骨架数据（欧普/公牛/佛山照明等 2024 年报数据）抽查**全部精确吻合**；39 张图表中 36 张有来源、33 张有解读。

**关键问题**：

1. **雷士照明沿革硬错误**：「2017 年退市、被吴长江团队收购」与史实不符（吴 2014 落马、2019 售予 KKR、主体仍以 2222.HK 挂牌），且与附录 A.1「雷士年报 2022-2024 来源港交所」自相矛盾；
2. **专利数据疑似虚构**：「飞利浦 Hue 约 10,000 件、松下约 8,000 件」整千整数无依据；欧普「累计专利 2,400+」与 ESG 披露 3,800~4,155 件矛盾；
3. **公牛毛利率 46.5%**（实际 43.25%）被代入第 9、12 章结论；
4. **时效口径矛盾**：生成于 2026-10 却漏掉欧普 2025 年报（2026-04 披露），2024 出口额标「预测值」且 388 亿美元对不上主流口径（约 423 亿）；
5. **[待核实] 红线名存实亡**：正文 0 处行内标注；附录 C 仅 10 条且 4 条逐字重复凑数。

### 3.2 一致性与结构审计 —— 判定：基线评审不予通过

1. **附录 B 术语表生成退化失控**：约 200 条「渠道孔子化/渠道 NFT 化/渠道刘敬化×3」伪术语，占第 13 章 2/3 篇幅——最典型的 LLM 重复退化，全书最严重质量事故；
2. **雷士 2024 营收 22 亿 vs 222.9 亿**（10 倍冲突，疑似小数点错位，出现在结论章）；
3. **表 4-1 份额体系失衡**：佛山（90.48 亿/1.27%）与公牛照明（83.31 亿/1.31%）营收份额倒挂；12 家合计与表末总口径差 2,300 亿；公牛份额在第 2 章（0.5%）与第 4 章（1.31%）两个版本；
4. **方向性矛盾集中**：流动比率「高于」（3 章）vs「低于」（9/12 章）行业平均；「营收连续两年下滑」与自家 2023 上升数据矛盾；欧普毛利率「次之」与自家数据（Yeelight/飞利浦更高）矛盾；
5. **跨章逐字复制**：第 2 章双碳段 ≡ 第 11 章；第 8 章 HCL 段 ≡ 第 11 章；第 12 章内容单薄同义反复。

**规律总结：第 3~9 章主体论据层质量尚可，第 10~13 章综合结论层与附录层明显失控。** 长任务后段质量衰减 + 无校验机制是主因。

## 4. Laya 评审首秀（评审链路验证）

### 4.1 协议与能力边界（实测确认）

- 端点：`POST /v1/systemone`（单条）/ `/v1/systemone/batch`（格式 `{"states": [...], "questions": {...}}`，共享问题集）；Bearer 鉴权；
- **state 窗口约 931 token**（超出静默截断，`usage.truncated` 可查）——必须切片评审；
- 请求体上限约 < 361KB（324 片全量单次 413），按章拆分（13 次调用）可行；
- 响应含逐题概率分布 + confidence，路由自动选 multilingual checkpoint；
- 评审切面设计：编造风险(score) / 来源可溯源性(choice) / 图表解读(noul) / 充实度(score) / 整体质量(score)。

### 4.3 Laya 评审机制结论（重要）

**Laya 单独定论不可靠，定位为「粗筛信号」：**

- 来源判定与人工/Claude 审计系统性不符：Laya 判 C（无来源）的块占比过半，实际全文有 199 处「数据来源」标注（多为 B 类模糊背书）——700 字切片内无引用属正常，Laya 把「本切片无标注」判成「无来源」，**切片粒度与问题设计存在系统性偏差**；
- Laya 未识别出审计发现的任何具体硬伤（雷士沿革、专利虚构、22/222.9 亿冲突）——**跨章一致性与事实核查超出其能力边界**（~1K token state 决定了它只见树木不见森林）；
- **正确的评审机制 = 分层**：Laya 做切片级粗筛（注水度、单切片风险信号）→ Claude（通用模型）做跨章一致性、事实核查、结构审计等深度评审 → 数字化校验（代码统计字数、查重、口径检查）做客观兜底。

## 5. 调优优先级建议（供第 1 轮调优立项讨论）

按「致命缺陷 × 发生频率 × Harness 可拦截性」排序：

| 优先级 | 问题 | 建议机制（Harness 层） |
|---|---|---|
| P0 | 生成退化失控（附录 B 伪术语 200 条） | 产出物自动校验：重复 n-gram 检测、退化模式识别，命中即打回重写 |
| P0 | 合并等机械操作由模型临时写脚本导致产物损坏 | Harness 提供可靠的内建合并/统计工具，产物自动可读性校验 |
| P1 | 跨章数值矛盾（22 vs 222.9 亿等） | data_ledger 机制强化：写章强制查台账 + 合并后数值一致性自动比对 |
| P1 | 结论层与论据层方向性矛盾 | 结论章生成前强制注入前文关键数据摘要；或结论-论据一致性校验环节 |
| P1 | [待核实] 红线零执行 | 硬约束周期重注入；合并后红线合规扫描（无来源精确数据检出） |
| P2 | 字数口径与自报失真 | 统一统计工具 + 禁止自报 |
| P2 | 记忆污染 / 日期错误 | 实验前记忆隔离；运行时上下文注入当前日期 |
| P3 | 长任务后段质量衰减（12 章单薄、13 章失控） | 章节质量门禁（Laya 粗筛 + 校验）逐章把关而非事后审计 |
