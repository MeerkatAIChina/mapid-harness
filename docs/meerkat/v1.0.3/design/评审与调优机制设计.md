## 1. 设计目标与原则

**目标**：让「生成 → 评审 → 调优 → 再生成」成为可重复、可度量、可收敛的 Loop，最终把 5 类致命缺陷压到零。

**原则**：

1. **分层评审**：客观的事给代码，单点信号给 Laya，综合判断给 Claude（通用模型）。
2. **最小拦截点**：机制尽量可插拔，不动内核语义。
3. **先校验后智能**：能用脚本判定的，绝不上模型。
4. **每轮可比**：每轮评审结果结构化存档，轮间可 diff。
5. **数据说话再前移**：检查器先在完稿后跑，积累命中率/误报率后，再决定哪些前移为章节级门禁。
6. **尺子先验准**：评审链各层（代码/Laya/Claude）的检出率本身要被金缺陷集回归验证，Claude 深审检出率达标，其「通过」判定才可采信。

## 2. 评审标准（维度表）

8 个维度。**D1/D3/D4/D5 为一票否决项**；D2/D7/D8 各自设合格线；D6 仅用相对判定（见 2.1）。

| 维度 | 对应缺陷 | 执行层（主/辅） | 具体检查项 | 合格线 |
|---|---|---|---|---|
| D1 事实真实性 | 编造事实 | Claude 定向审（主）+ 代码扫描（辅） | 定向三层审法（3.3）；**时效性检查：关键公司财务数据必须引用最新一期披露** | 高危清单 100% 核查通过；无来源精确数据 = 0 或全部标 [待核实]；无陈旧数据 |
| D2 数值准确性 | 数值漂移 | 代码（唯一） | 字数统计（禁止模型自报）；正文数值与结构化台账匹配（2.2） | 字数口径统一（非空白字符数）；台账覆盖率 100% |
| D3 结论友好偏置 | 结论友好 | Claude 深审（唯一） | 判据置换检测（定义见 2.3） | 0 处判据置换 |
| D4 跨章一致性 | 一致性偏差 | 代码（主）+ Claude（辅） | 台账内查重 + 正文数值与台账匹配（脚本）；Claude 抽查定性矛盾 | 数值 0 冲突；定性 0 矛盾 |
| D5 硬约束遵守 | 约束遗忘 | 代码（唯一） | [待核实] 行内标注；台账新鲜度；交付物清单齐全 | 全部硬性检查通过 |
| D6 内容充实度 | （质量） | Laya 粗筛（主）+ 代码（辅） | Laya content_density + fabrication_risk 全量切片；代码重复 n-gram/退化检测 | 退化检测 0 命中；Laya 用相对判定（2.1） |
| D7 图表配套 | （质量） | 代码（唯一） | 每张图/表 ±窗口内有来源标注和解读 | 配套率 100% |
| D8 结构完整性 | （质量） | 代码（主）+ Claude（辅） | 章节齐全、无空壳章、无逐字重复段落 | 结构检查通过 |

### 2.1 Laya 评分的使用规则

- **绝对阈值缓行**：R1 不执行「充实度 ≥3.0」类阈值（基线 2.69 受附录 B 退化污染，修好前无法归因）。阈值在 R1 实测分布出来后定（分布右侧留 margin）。
- 过渡期用两个相对指标：**轮间均值比较**（看方向）+ **单章离群检测**（低于全文均值 1 个标准差 → 打回该章）。
- **已砍题**：`source_traceability`（把「本切片无标注」系统性误判为「无来源」，纯噪音）。
- 保留题目：`fabrication_risk`(score) / `chart_interpretation`(noul) / `content_density`(score) / `overall_quality`(score)。

### 2.2 数据台账结构化 schema（R2 核心设计物，此处先立契约）

自由文本上的数值比对 = NER + 单位归一 + 口径对齐，不可靠（"22亿" vs "222.9亿" vs "2,229,000万"）。故 `data_ledger` 从自由 Markdown 改为**结构化表格**（csv 或固定列表格），字段：

```
指标名 | 数值 | 单位 | 口径/年份 | 来源 | 首现章节
```

比对方式随之简化为：**台账内查重（同指标不同值即冲突）+ 正文数值与台账匹配**。提示词 v3 同步改台账格式要求。

### 2.3 D3「判据置换」操作性定义

> **定义**：结论章的论断所依据的评价标准，与论据章实际呈现的数据所支持的标准不一致，且未说明判据为何变化——即不是「看错了数据」（那是 D4），而是「换了一把尺子来迎合想要的结论」。

- **反例（判据置换）**：论据章数据显示欧普毛利率 39.3% 低于 Yeelight 40.0%，结论章却称「欧普盈利能力行业领先」——评价时悄悄把尺子从「毛利率数值」换成了未声明的其他标准。
- **正例（非置换）**：结论章称「欧普盈利能力在头部传统照明企业中领先」，且明确限定比较范围为「传统照明企业」（排除新生态品牌）——判据变化被显式声明，允许。

## 3. 评审流程

### 3.1 检查器与门禁分离

门禁的本质 = 同一检查器从「完稿后跑一次」变成「每章写完跑一次」，挂载点变了，检查器没变。因此：

- **R1 只做检查器**：独立可复用模块（退化检测、字数统计、台账新鲜度、数值比对、图表配套、结构检查），在完稿评审中运行，积累命中率/误报率；
- **跑 1~2 轮后**，高频命中且误报可控的检查才前移为章节级门禁；没命中的说明问题已在别处修掉；
- **提示词层软门禁**（零代码，R1 即上）：任务提示词要求每章写完执行自检清单——「台账更新了吗？本章数值与台账一致吗？无来源精确数据标 [待核实] 了吗？」只引导不拦截。

### 3.2 完稿后报告级评审（R1 唯一评审点）

```
Step 1 代码全量校验（D2/D5/D7/D8 + D4 数值比对 + 退化扫描）→ 产出高危清单
Step 2 Laya 全量切片粗筛（D6 充实度 + fabrication_risk）
Step 3 Claude 定向深审（D1/D3/D4 定性，审法见 3.3）
Step 4 汇总《评审报告.md》：逐维度得分 + 证据 + 通过/不通过判定
```

### 3.3 Claude 定向深审三层法

| 层 | 审法 | 理由 |
|---|---|---|
| 代码扫出的「无来源精确数值」清单 | **100% 全审** | 高危集合，规模可控 |
| 结论章（12/13）+ 附录 | **全审** | 基线规律：论据层尚可、结论层失控 |
| 正文第 3~11 章 | 每章随机 1 个 | 低密度区保底 |

## 4. 调优 Loop 机制

```
单轮 Loop：
  ① 准备：隔离/清理 agent 记忆（防污染），新建干净 thread
  ② 执行：当前版本提示词 + 当前 Harness 版本跑报告任务
  ③ 观察：trajectory + workspace 巡检（research/观察记录方法.md）
  ④ 评审：按第 3 节产出《评审报告.md》
  ⑤ 归因：缺陷 → 分层定位（提示词层 / 编排层 / Harness 代码层 / 模型服务端）
  ⑥ 调优：最小改动包——按归因层打包（工具层/机制层/提示词层），
          包内每项改动可通过单测或快速轮单独验证，轮间 diff 可归因到层
  ⑦ 存档：提示词版本 + Harness commit + 评审报告 + 对比 diff
          + changes.md（本轮改动 + 预期影响的维度清单，轮间验证"只动了预期维度"）
          → docs/meerkat/v1.0.3/rounds/round-N/
  ⑧ 汇报：Claude 向用户汇报本轮结果与下轮计划，用户批准后进下一轮
```

### 4.1 双轨轮次与金缺陷集（评审链整体回归）

| 轮次类型 | 定位 | 规模 | 用途 |
|---|---|---|---|
| **快速轮（smoke test）** | 验证「机制是否生效」 | 固定 5 章缩量（约 3 万字）+ 注入金缺陷 | 验证检查器与评审链真的能拦住 |
| **全量轮** | 收敛判定专用 | 完整 10 万字 | 只有全量才暴露后段衰减 |

**金缺陷集**（v3.1 修订：可注入性筛选 + 固定宿主）：基线已确认的约 20 项缺陷按「能否文本注入」分两类：

```
golden_defects/
├── text_injectable/    # 审计发现 12 项 + 文本类工作链缺陷（字数失真、口径混乱、
│                       #  附录退化、台账停更的伪造状态）→ 供评审链回归注入
└── process_checklist/  # 过程性缺陷（stream_error、记忆污染、合并损坏、日期错误）
                        # → 无法文本注入，由各自机制的验收项覆盖
                        #   （断流续跑→收敛条件5、记忆隔离→Loop①检查单）
```

回归方法（v3.1 修订：**固定宿主，不每轮重新生成**）：

1. 宿主文本固定为基线 `report_merged.md` 的章节切片——同一宿主 + 同一缺陷，轮间检出率的唯一变量就是评审链版本，可比性最强且成本最低；
2. 把 text_injectable 金缺陷注入宿主 → 跑完整评审链（代码 + Laya + Claude 三层）→ 统计各层检出率；
3. **Claude 深审检出率 ≥90%，其通过判定才可采信**——不能在会漏检的尺子量出的「合格」上宣布收敛。

> 执行注记（2026-10-20，R1 落地细化）：切片宿主服务 Claude/Laya 层；**检查器层**回归宿主
> 为冻结的完整 workspace `baseline/baseline_workspace/`（台账/progress 状态文件是 META 型
> 缺陷的检出前提，纯文本切片不够）。两层宿主各自固定，可比性原则不变。

快速轮产物的本职用途回归为：验证提示词软门禁是否真的引导了模型行为。快速轮**不能**用于验证「问题是否解决」，缩量版里没有「第 12 章」。

### 4.2 R1 范围

1. 检查器模块（完稿后跑）：退化检测、字数统计、台账校验、数值比对、图表配套、结构检查；
2. 内建合并/统计工具（替代模型临时写脚本）；
3. 提示词 v3（自检清单软门禁 + 台账结构化格式 + 「财务数据先搜后写」）；
4. **断流自动续跑**（调优流程自身的基础设施：连跑多轮时每次 stream_error 浪费 14 分钟人工盯守）；
5. 记忆隔离流程 + 当前日期注入；
6. 金缺陷集素材库建设。

## 5. 收敛标准（TODO ⑥）

满足全部条件即收敛：

1. 一票否决项（D1/D3/D4/D5）全部合格；
2. **D2/D7/D8 各自合格 + D6 仅离群判定**（务实版，替代权重未定的加权 85 分；权重与映射规则待 R1 数据校准后回补）；
3. **金缺陷集回归检出率 ≥90%（评审链三层分别统计）且全量轮检查器无命中**；
4. **连续 2 轮全量轮**无新增缺陷；
5. **全量轮全程 0 次人工干预**（断流自动恢复、无人工「继续」）——同时是 R1 断流续跑的验收标准。

止损线：单项机制连续 3 轮无改善 → 上报用户讨论调整目标或接受现状。
