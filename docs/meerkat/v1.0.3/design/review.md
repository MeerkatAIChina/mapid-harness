## 第 1 轮评审（针对 v1 草案，2026-10-19）

4 个决策点逐一给出明确建议（结论先行）：

### 1. 章节门禁 → 第一版只做完稿后评审，但换个实现思路

不先做 middleware，把「检查器」和「门禁」拆开做。门禁本质是把同一个检查器从「完稿后跑一次」改成「每章写完跑一次」，挂载点变了，检查器本身没变。正确顺序：

- R1 先把检查器做成独立可复用模块（退化检测、字数统计、台账新鲜度校验），在完稿评审里跑——顺便验证命中率和误报率；
- 跑 1~2 轮后，看哪些检查真正高频命中且误报可控，再把这几个前移挂到章节级。没命中的检查说明问题已在别处被修掉，根本不需要门禁。

同时零成本加提示词层软门禁：每章写完执行自检清单（台账更新了吗？本章数值与台账一致吗？无来源精确数据标 [待核实] 了吗？）——不拦截，只引导，不改一行代码。

直接做 middleware 的风险：不知道哪些检查值得硬拦截、误报率多少，可能拦截一堆假阳性，反而把 78 分钟的生成搞得更长。

### 2. 合格线 → 代码判定项不校准，模型分必须先校准，≥3.0 不能直接执行

- D4 数值冲突、D5 硬约束这些代码判定的：不校准。0 冲突就是 0 冲突。
- Laya 充实度 ≥3.0：先别执行。归因问题：基线 2.69 里相当一部分低分是附录 B 伪术语贡献的，R1 修掉退化后均值必然上涨——涨到 3.0 分不清是「阈值定得合理」还是「恰好修掉了最大拖分项」。阈值应该在 R1 实测分布出来后再定（分布右侧留 margin）。
- 校准之前 Laya 分数的用法改成两个相对指标：轮间均值比较（看方向）+ 单章离群检测（某章低于全文均值 1 个标准差 → 打回该章）。「哪一章坏了」比「均值 2.9 还是 3.1」可操作得多。
- 顺手砍掉 source_traceability 题——基线已证明它把「本切片无标注」系统性误判成「无来源」，纯噪音源。

### 3. 快速轮 → 设，但定位必须是 smoke test，且要"埋雷"

3 万字快速轮只能验证「机制是否生效」，不能验证「问题是否解决」——后段衰减（10~13 章失控）只在全量下暴露。所以：

- 快速轮 = 固定 5 章缩量 + 故意埋 1~2 个金缺陷（伪术语退化段、台账外精确数值），验证检查器真的能拦住；
- 全量轮 = 收敛判定专用；
- 断流自动续跑从 P2 提到 R1：连跑多轮时每次 stream_error 浪费 14 分钟人工盯守，这是调优流程自身的基础设施。

### 4. 抽检 → 每章 3 个不够，换范式：随机抽样 → 定向全审

基线已证明随机抽会漏：公牛毛利率 46.5%（实际 43.25%）的错误值被代入第 9、12 章结论。改成三层定向：

| 层 | 审法 | 理由 |
|---|---|---|
| 代码扫出的「无来源精确数值」清单 | 100% 全审 | 高危集合，规模可控 |
| 结论章（12/13）+ 附录 | 全审 | 论据层尚可、结论层失控，错误集中区 |
| 正文第 3~11 章 | 每章随机 1 个 | 低密度区保底 |

成本上与 13×3=39 条随机抽检相当，召回率完全不同量级。

## 第 2 轮评审（针对 v2 修订稿，2026-10-19）

### 总评

4 个决策点全部正确采纳，核心框架已站得住，可以定稿。剩下：1 处自相矛盾必须修，2 个机制缺口强烈建议补，若干小问题。

### 必须修：§4⑥ 与 R1 范围自相矛盾

Loop 第 ⑥ 步仍写「一轮只改一类问题，保证可归因」，但 §4.2 的 R1 范围打包了 5 项内容（检查器 + 合并工具 + 软门禁提示词 + 断流续跑 + 记忆隔离/日期注入）。两处打架。

建议改为：**「最小改动包：按归因层打包（工具层/机制层/提示词层），包内改动各自可通过单测或快速轮单独验证，轮间 diff 才能归因到层」**。归因性真正要求的是「这轮起效的是哪一层」，不是「5 个工具里哪个起效」——后者用金缺陷集和单测就能分辨，不需要牺牲整轮实验。

### 强烈建议补的两个缺口

**1. 评审器信度只覆盖了一半**

§4.1 埋金缺陷验证的是代码检查器能拦住，但评审链还有 Laya 和 Claude 深审两层，它们的 recall 没验证——而收敛判定最终信的是 Claude 深审的「未发现问题」。建议把埋雷扩展为评审链整体回归：

- 金缺陷集 = 基线已确认的约 20 项缺陷（8 项工作链 + 12 项审计发现）建成可注入素材库；
- 每轮正式评审前，把金缺陷注入快速轮产物 → 跑完整评审链（代码 + Laya + Claude）→ 统计三层各自检出率；
- Claude 深审检出率达标（如 ≥90%），它的通过判定才算数。否则可能在一把会漏检的尺子量出的「合格」上宣布收敛。

**2. 收敛标准仍缺「执行可靠性」**

§5 四个条件全是评产物的。加第 5 条：**全量轮全程 0 次人工干预**（断流自动恢复、无人工「继续」）。这条同时是 R1 断流续跑改动的验收标准，一举两得。

### 其余问题（按重要性排）

3. **D2/D4 数值比对仍落在自由文本上**：自由文本数值提取 = NER + 单位归一 + 口径对齐，工程量大且不可靠（"22亿" vs "222.9亿" vs "2,229,000万"）。建议 data_ledger 改结构化 schema（csv/固定表格：指标、数值、单位、口径、来源、首现章节），比对 = 台账内查重 + 正文数值与台账匹配。台账 schema 是 R2 的核心设计物，应单独立节，提示词 v3 同步改台账格式要求。
4. **加权 85 分算不出来**：权重没定义；「各层输出归一化」映射没定义（Laya 2.69/4 怎么映射到 0~100？）；D6 阈值缓行期间 D6 对 85 分的贡献是什么？建议：要么补权重表和映射规则，要么收敛条件 2 临时改为「D2/D7/D8 各自合格 + D6 仅用离群判定」——后者更务实。
5. **D1 缺时效性检查**：基线漏掉欧普 2025 年报（2026-04 已披露）这类「数据陈旧」不在任何检查项里。D1 加「关键公司财务数据必须引用最新一期披露」；提示词层对应加「财务数据先搜后写」。
6. header 引用的 review.md 不存在（dangling reference）。→ 本文件即为补建。
7. **D3「判据置换」无操作性定义**：8 维度里最难自动判的，没有定义和正反例，Claude 深审轮间评分不可比。给 2~3 句操作性定义 + 基线式正例/反例。
8. 收敛条件 3「检查器生效且无命中」措辞歧义——「无命中」分不清是「修好了」还是「检查器没跑」。改为「金缺陷集回归检出率 ≥90% 且全量轮无命中」。
9. rounds/round-N/ 存档清单建议加 `changes.md`（本轮改动 + 预期影响的维度清单）——轮间 diff 时验证「改动是否只动了预期维度」，归因证据链闭环。
