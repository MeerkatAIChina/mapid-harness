```text
任务：欧普照明竞品分析深度报告

核心工作方式（最高优先级，先于一切内容要求）
本任务是一份 10 万字量级的长报告，单次回复不可能装下全文，这是工程事实而非偷懒借口。你必须采用「分章写文件」的工作方式，通过文件系统工具在工作目录中逐章产出，最终用内建工具合并为完整报告。具体要求：

1. 先规划后写作：第一步必须先写出大纲文件 outline.md（章节目录 + 每节要点 + 各章数据来源计划 + 每章非空白字符下限分配，13 章下限合计不得低于 105,000），然后再开始动笔。
2. 逐章产出：每个一级章节写入独立的 Markdown 文件（chapters/01_研究背景.md、chapters/02_行业全景.md ……依此类推）。每次 write_file 调用只写一节内容（单节控制在 2000–4000 字），一章分多次调用写完，严禁试图在一次回复中输出整章甚至全文。
3. 每章验收（行动顺序，做完才准写下一章，缺一不可）：
   a. 用 report_stats 实测本章字数——低于 outline 分配的下限，必须围绕「二、篇幅与结构要求」的加深方向加厚重写本章，重新实测达标后才可继续；
   b. 把本章关键数值登记进 data_ledger.md（结构化表格，见下），含首现章节列；
   c. 核对本章数值与台账已有条目一致（同指标同数值同口径）；
   d. 确认本章无法查证的数据已标注「[待核实]」（规则见「五、数据真实性硬性要求」）；
   e. 确认本章所有图/表都配齐了来源行与解读段（见「四、图文并茂要求」），缺则当场补上；
   f. 确认本章末尾已设「## 本章参考资料」节：本章正文引用的每个 [n] 编号都有对应条目，且每条条目都被正文至少引用一次；
   g. 若 report_stats 返回中出现 [chapter_gate] 段落，其中列出的每项检查问题必须逐条修复、再次调用 report_stats 复测通过后才准写下一章；若写文件被门禁阻断（返回错误），先修复所指章节再继续，禁止绕开。章节文件一律经 write_file/edit_file 写入，禁止使用脚本或 execute 工具绕过内建工具写章节文件。
4. 维护进度台账：每完成一章更新一次 progress.md，记录已完成章节、待办章节、写作中发现的问题。注意：progress.md 中禁止自报字数，字数统计一律使用 report_stats 工具的结果。
5. 维护数据台账（结构化）：data_ledger.md 格式必须是如下表格，禁止自由文本：

   | 指标名 | 数值 | 单位 | 口径/年份 | 来源 | 首现章节 | ref |
   |---|---|---|---|---|---|---|
   | 欧普照明营业收入 | 70.96 | 亿元 | 2024年报 | 欧普照明2024年年度报告 | 03 | 3 |

   报告中出现的所有关键数值（市场规模、财务数据、份额、技术参数）都必须登记。后续章节引用同一数据时，必须先查台账，保证全文数值、单位、口径完全一致。
   **ref 编号注册中心（引用取号流程）**：每引用一个新来源，先在 data_ledger.md 登记一行并分配 ref 编号——取号 = 台账当前最大 ref + 1，全书唯一，同一来源全书固定一个号；正文、图表引用该来源时只能使用已登记的编号，禁止使用未登记编号。
6. 合并交付（字数目标 + 诚实出口）：全部章节完成后，先用 report_stats 统计全部章节总量，非空白字符数达到 100,000 再调用 merge_chapters 合并；若内容已充分而不足 100,000，在 progress.md 与结论章如实说明实际字数与理由后直接合并——禁止以任何形式凑字数（宁可不足，不可复制）。严禁自己编写脚本或手动拼接合并。合并后再用 report_stats 统计合并稿，把工具输出原样写入 progress.md。

一、任务主题
撰写一份欧普照明（Opple Lighting）竞品分析深度研究报告，全文字数目标 10 万字（中文，以非空白字符数计）。

二、篇幅与结构要求
- 全文展开为多章节、多层级的完整报告（建议 12–15 个一级章节，每章下设 3–6 节），严禁只输出大纲充数。
- 每章非空白字符下限由 outline 分配（各章 6,000–12,000 之间按内容权重分配），合计不低于 105,000；单章下限分配不得超过 12,000——不得为凑总量给单章堆超额下限，内容超出 12,000 的章必须拆分（竞品逐家章拆为两章，每章覆盖竞品不超过 5 家）。
- 内容不足以达字数时，围绕以下方向加深加厚，而不是注水：
  - 欧普照明 vs 雷士照明、佛山照明、三雄极光、阳光照明、公牛集团、木林森、飞利浦（昕诺飞）、欧司朗（艾迈斯欧司朗）、松下照明、Yeelight/小米生态链等竞品的逐家深度拆解；
  - 各竞品的产品线矩阵、价格带分布、渠道结构（线下经销/五金渠道/电商/工程集采/海外）逐一对比；
  - 智能照明赛道（Matter 协议、全屋智能、人因照明 HCL）的技术路线对比；
  - 财务指标多年度纵向对比（营收、毛利率、净利率、研发投入占比、存货周转等）。

三、建议章节框架（可扩展）
1. 研究背景、方法与数据来源说明
2. 中国及全球照明行业全景：市场规模、增速、产业结构、政策与标准（能效标准、双碳政策影响）
3. 欧普照明公司深度剖析：发展历程、股权与治理、业务结构、财务分析、战略路线
4. 竞争格局总览：市场份额、梯队划分、竞争五力分析
5. 重点竞品逐家深度分析（每家独立成节：公司概况、产品、渠道、财务、优劣势；竞品超过 5 家时拆为两章）
6. 产品线与技术参数横向对比：光源效率、显色指数、色温范围、智能协议支持、质保等
7. 渠道与营销对比：渠道结构、终端网点数量、电商表现、品牌投放
8. 智能照明与新技术布局对比：专利分析、协议生态、全屋智能合作
9. 财务与经营指标综合对标（多年度）
10. SWOT 与战略群组分析
11. 行业趋势研判与欧普照明的机会/威胁
12. 结论与战略建议
13. 附录：全书参考资料总表（全书所有 [n] 条目汇总）、术语表、待核实数据清单

四、图文并茂要求（每张表格/图按模板执行，缺一视为该节未完成）
- 使用 Mermaid 图表、Markdown 表格、文本示意图呈现市场份额、财务趋势、对比矩阵等；
- 每张图/表之后必须紧跟两行，缺一不可：
  1. 来源行：`> 数据来源：[n]`（编号对应本章末「本章参考资料」条目，该条目须含数据期）；
  2. 解读段：≥2 句的数据解读，说明该图/表支撑什么判断；
- 写完一节就检查本节的图/表是否都配齐了来源行与解读段，缺则当场补上。

五、数据真实性硬性要求（红线，优先级高于篇幅）
- 口径标注：所有关键财务与市场数据首次出现时，必须注明口径主体与数据期，格式为「主体 + 数据期 + 指标 + 数值」（例：欧普照明2024年报营收70.96亿元）。市场份额、集中度（CR n）类数字必须注明分母口径（整体市场 / 细分品类 / 渠道类型）；未注明分母口径的份额数字，禁止出现在结论章。
- 来源标注（顺序编码制，段落级动作）：每个含精确数值的段落，写完立即检查——数值后带引用编号 `[n]` 吗（例：营收 70.96 亿元[3]，表格格子同样规则：39.3%[12]）？没有来源的先补检索，检索不到当场标注「[待核实]」，禁止凭印象填数、禁止留到章节末尾再补。
  - 编号对应章末「## 本章参考资料」节条目，条目格式：`[n] 机构《报告名》，年份，披露渠道/URL[，页码]`（例：`[3] 欧普照明《2024年年度报告》，2025，上交所披露平台`）；章末只列本章用到的条目；
  - 新来源必须先在 data_ledger.md 登记取号（ref 列），编号全书唯一；
  - 三条禁令：禁止正文出现章末无对应条目的编号（悬空引用）；禁止章末列正文无人引用的条目（孤儿条目，凑数假装饰）；禁止使用台账 ref 列未登记的编号。
- 雷同值禁令：对比表格中不同主体的同一参数禁止整行/整列雷同值（如四家企业寿命同为 25,000/30,000/50,000 小时）——出现雷同即视为凭印象填数，必须检索差异化数据或逐格标 [待核实]。
- 时效性：涉及公司财务数据时，必须先搜索确认该公司最新一期已披露的财报（年报/季报），引用最新数据，禁止使用过期的旧数据而不自知；行业数据优先采用最近年份的权威发布。
- 数据来源必须是真实可查证来源（年报/招股书、国家统计机构、行业白皮书、券商研报、官方标准、专利数据库）。严禁虚构数据，严禁用"看起来合理"的经验数字填充，严禁虚构或张冠李戴公司股东、高管、实控人姓名——无法确认主体名称时标注「[待核实]」，宁可空缺不可编造。编造来源条目（虚构报告名、虚构披露渠道）与编造数据同罪。
- [待核实] 的使用（三段式降级）：财务核心表格（营收/利润/毛利率等对标表）的主体数据必须先经检索获取；检索不到时——
  ① 单表 [待核实] 格子 ≤20%（分母 = 该表数据格总数，不含表头/单位/备注行）→ 保留表格；
  ② 超过 20% → 先删行保表：剔除无据的数据行，并在表下注明覆盖范围（例：覆盖 7/10 家企业）；
  ③ 删行后仍超过 20% → 整表降级为定性文字表述。
  [待核实] 永远是最后手段，不是默认选项。
- 所有「[待核实]」数据在附录汇总为《待核实数据清单》表：数据项、所在章节、建议核实来源。
- 同一数据在全文多处出现时，数值、单位、口径必须与 data_ledger.md 台账完全一致，禁止前后矛盾。
- 结论章专项：结论章的每条数字论据必须标注出处章节（格式：「（见第 X 章）」），且数值、区间、口径必须与前文一致；结论章不引入前文未出现的新关键数据，确需合成指标（如加权评分），必须写明计算方式与数据来源章节；每条论断必须能在前文找到对应论据；评价标准（比较对象、指标）在全文中保持一致，如需更换比较口径必须显式说明理由。

六、语言与交付
- 全文简体中文；术语首次出现附英文原词。
- 交付物：outline.md、data_ledger.md（结构化表格含 ref 列）、progress.md、chapters/ 目录下全部章节文件、经 merge_chapters 工具合并的完整报告。
```

## v5 → v6 变更对照（骨架阶段）

| 项 | v5 | v6 | 对应缺口（R3 实测/设计依据） |
|---|---|---|---|
| 来源标注样式 | 段内「数据来源：<报告名>（<数据期>）」 | 顺序编码制：数值后 `[n]` + 章末「本章参考资料」节集中列示（结构化条目） | R3 假来源在段内标注里格式完美即蒙混；集中靶场便于核验（设计 §2） |
| 编号分配 | 无 | 台账加 ref 列当注册中心：新来源先登记取号（全书唯一），正文才可用号 | 杜绝重号，机制支撑不靠模型记忆（澄清议题③） |
| 引用检查口径 | 「数值附近有来源标注」 | 三级判定：标记 + 悬空引用 + 孤儿条目 + 未注册编号 | 后两种正是假来源温床（需求 §4） |
| 图表来源行 | `> 数据来源：<来源名>（<数据期>）` | `> 数据来源：[n]`（条目含数据期） | 与正文同制 |
| 附录 | 数据来源清单 | 全书参考资料总表（[n] 条目汇总） | 全书统一编号池落地 |
| 虚构来源 | 未单列 | 「编造来源条目与编造数据同罪」明示 | R3 最重要发现（虚构上市+虚构年报） |
