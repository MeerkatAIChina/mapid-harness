## 四、新发现 bug（octop 侧，只记录不修）

### bug ⑥ 会话内容消失变欢迎页（2026-11-05 17:15 用户报告，前几个 round 也出现过）

**现象**：长任务进行中，dashboard 当前会话消息区变空白欢迎页（Hi~ 来和智能搭档一起探索吧），
侧边栏会话仍显示进行中（转圈），输入框有停止按钮。服务端任务不受影响。

**证据链**：

1. 当前会话（thr_01M6NAJ78…）`thread_messages` = **0 行**，而 round-7 已完成会话 = 224 行
   → 消息**只在 turn 结束时落库**，进行中历史 API 必返回空；
2. 进行中的内容只能经 WS 实时流渲染；本轮 15:45 / 16:12 两次 `ws hub: push failed`
   （与 bug④ 同源的 WS keepalive 判死）→ 页面刷新或 WS 死亡后，实时缓冲丢失 + 历史为空
   = 欢迎页；
3. `thread_history_projection` 有 1 行、history API 有 `turn_active` 概念，但前端
   重进会话时未凭 turn_active 重挂到进行中的流（或重挂后无缓冲可放）。

**定性**：bug ③④ 同族（WS 可靠性），但症状独立（③是重放旧内容，⑥是内容全无）。
叠加设计缺陷：消息不落库直到 turn 结束——长任务（小时级单 turn）把这个缺陷放大成
「全程不可见」。**不影响任务本身，仅影响可观测性。**

**补充（17:21 用户实证）**：刷新后内容「有时候忽然出现但有缺失」——截图显示前端其实
**有重挂机制**（重进后能接到进行中的实时流，显示「正在调用工具」「report_stats 执行中」
等尾部事件），但只能看到**重挂时刻之后**的新事件；turn 开始到现在的全部内容既不在历史
（未落库）也不在新流里（只发增量）→ 中段永远缺失。「有时候完全不出现」则取决于刷新瞬间
WS 是否已判死（两次 push failed 时段内刷新 = 欢迎页；WS 健康时刷新 = 尾部流）。
即：重挂存在但无回填（no backfill），是⑥的第二层缺陷。

**修复方向（记录，不动源码）**：a) turn 进行中增量落库或 projection 实时可查（根治：
回填有源）；b) 前端重挂流时向服务端请求「本次 turn 已累计事件」做回填；c) 与 bug④
合并根治 WS 判死（HTTP cancel + keepalive 参数）。

## 七、merge 前循环死锁（11-06 14:40 确诊，本轮人工止损）

**现象**：ADR-002 修复上线后，merge 仍无法通过。notes 轨迹 88→22（重分类生效）
→ 17 → 11 → 13 → 10 → 22 → 22，振荡不收敛；脏章反复出现（02/03/06/08 多次
 dirty→clean→dirty）。

**根因（结构性，三工序互相重置状态，无收敛机制）**：

1. agent 处置 notes 必须改文 → `编辑即清`（chapter_gate `_post_tool_call`）
   把 verified 和 **reviewed 一起重置**；
2. 下次 merge 触发自动审校（`_merge_autoreview` 只认 reviewed 标志）→
   审校模型 5+ 轮以来**每轮必改 1-9 处，从不零改动**；
3. 审校改文 → verified 又清 → 重核 → 抽取器对改后文本**重新抽取**（措辞漂移）
   → 新的无编号断言 → 新 notes → 处置 → 改文 → reviewed 再重置 → 回到 2。

出口条件（全章同时：审校零改动 + 核验通过 + notes 清零）在「审校永不零改动」
的实测行为下不可达。**单靠凭证结案（ADR-002）救不了这个死锁**——它解决的是
notes 的存量口径，不解决三工序互相重置的循环动力。

**本轮止损（人工清场，非机制修复）**：停机后人工修脏章证伪 + 22 条无编号断言
正文标 [待核实] + 重写 gate_state（全章 clean/passed/reviewed）→ merge 直通
交付链。状态手术的前提：服务器停止（运行中门禁的内存状态会覆盖磁盘手术结果）。

**R5 候选修复（记录待办，本轮不动代码）**：

- 审校收敛上限：每章自动审校 ≤N 轮（如 3），之后只标记不再改文——保证终止性
  （review 是润色工序，真实性由核验兜底，截断代价可控）；
- 增量重核：断言绑定正文行号区间/段落指纹，编辑只重核受影响断言（解决整章
  重核 × 抽取漂移的双重放大）；
- 断言规范化键：缓存键对齐事实（实体+数值+口径）而非措辞，提升缓存命中率
  （本轮 45%）。
