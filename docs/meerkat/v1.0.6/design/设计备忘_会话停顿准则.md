# 设计备忘：会话停顿准则（汇报不停手，决策带建议）

> 2026-11-04 round-6 运行期间与用户讨论定稿。起因：模型在第 2/3 章边界
> 以「单次回复字数限制，无法一次完成 13 章」为由停下来等「继续」——
> 该理由是假的（章节走 write_file 落盘，不经过聊天回复），暴露出
> 「什么时候该停、怎么停」缺少行为准则。

## 三分类准则

| 类型 | 行为 | 举例 |
|---|---|---|
| 汇报性 | **不停手**：写 progress.md 或说一句就继续干活 | 「第 3 章完成，开始第 4 章」 |
| 事故性 | 停，且必须让人看得见（不允许静默） | 空响应重试耗尽、工具连续失败 |
| 决策性 | 停，且**必须附：现状 + 选项 + 我的建议** | 「来源 A/B 数据打架，我倾向采信 A 因为……，你定」 |

要点：

1. 汇报的价值是让人**知道**，不是让人**批准**——批准才有成本。
2. 决策性提问必须带模型的推荐方案：模型是干活的，最了解现场；
   不带建议的提问等于把调研成本扔回给人。人的介入应压缩到
   「同意 / 不行」十秒级别。
3. 事故性停止已由机制保证可见（空完成护栏 f2290f0：耗尽后转可见
   错误 turn，不再静默收尾）。

## 留待决策

- **决策性停止是否配「超时按建议执行」**：模型带建议停下后，N 分钟
  无人响应则按建议继续并记档。好处是无人值守不瘫痪；风险是模型
  变相自我授权。用户未定。

  决策点必须带建议」（下个版本需求描述收录）。
