# 设计文档_R4：真实性与成品交付

> 版本：v1.0.6 · 2026-11-03 · 输入：`requirement/需求描述_R4.md`（16 项）、`需求调研_R4.md`（可行性+5 新发现）、`需求澄清_R4.md`（四议题定稿）
> **内核改动声明：零。** 全部改动落在 harness 层（检查器/中间件/插件/工具）与提示词层，Octop 内核不动。

## 1. 总体架构：三道防线 + 两条交付链

```
写作期（章级，主战场）
  章写完 → report_stats → 门禁四件套（来源格式/图表题注/台账/退化）
        → 【新】第五道：承重断言核验（独立模型+检索+抓取，三档判定）
        → 【新】字数不足 → 续写指引（≤3 轮，独立预算）
        → 全过 = clean → 才准开新章

成书期（merge 前，复查）
  merge_chapters → 全量六检查器 + 跨章核验
        → 【新】审校链（独立模型文字编辑：行号最小编辑，改完章置 dirty 复测）
        → 【新】出口举证核验（未达标章的要点覆盖映射）
        → 全过才放行合并；N=2 放行阀保留 + 放行落盘追踪

交付期（只兜底，不查事实）
  【新】残留清理（三层+中文禁词）→ 图表生产（挂台账）→ 同源渲染三格式
  → 交付验收断言（占位符/残留/格式/三件套完整性）
```

**设计总原则**：①确定性工序脚本化（同事管线实证有效的部分）；②内容真实性由机制强制
（我们的既有优势）；③凡新闸门必配金缺陷回归用例（「断言写了≠断言守住」的对标教训）。

## 2. 子包 Y：引用系统改造（承重墙，一切先行）

**需求来源**：C5 + A1 的靶场前提。**顺序钉死：先改引用格式，再改检查器**（顺序反了回归全崩）。

### 2.1 格式契约（澄清议题③定稿）

- 正文：精确数值带顺序编码标记 `[n]`（如 `39.3%[12]`）；表格格子同规则；
- 章末：「本章参考资料」节，条目结构化：`[n] 机构《报告名》，年份，披露渠道/URL[，页码]`，
  只列本章用到的条目；
- **全书统一编号池**：同一来源全书一个号；附录列总表；
- **台账加 `ref` 列当注册中心**：新来源先在 data_ledger.md 登记取号，正文才可用号——
  编号分配有机制支撑，杜绝重号。
  **表头契约处理（builder-check 修正）**：`LEDGER_FIELDS` 本身**不动**——`_header_covers` 是
  覆盖判定（`set(LEDGER_FIELDS) <= 表头`），若把 ref 塞进 LEDGER_FIELDS，没有 ref 列的旧台账
  （round-4 产物、回归脚本伪造表）全部不合规 → `check_numeric_consistency` 会跳过这些表 →
  GD-07/GD-09 检出路径静默失效、回归 TP 崩。正确做法：ref 列为**过渡期推荐列**，由
  `citation_ledger_ref` 检查器单独管——台账有 ref 列时才执行编号注册核对；旧宿主（无 ref 列）
  自动豁免，与新样式章并存。

### 2.2 检查器改造（三级判定，需求 §4 钉死）

| 检查器 | 改动 |
|---|---|
| `unsourced_precise` | 判定改「数值 ±N 行有 `[n]` 或 `[待核实]`」；**双样式过渡且永久保留**（builder-check 修正：若验证轮后下线旧式，冻结的旧回归宿主的「来源：」标注全部失效、TP/FP 全崩——双样式不是过渡是长期并存，兼容成本仅一条正则分支） |
| `figure_companion` | 题注来源接受 `[n]` |
| `conclusion_source` | **不动**——结论章保留「（见第 X 章）」锚点制（设计裁定：缩小改造面，锚点与 [n] 职责不同） |
| 【新】`citation_dangling` | 悬空引用：正文 [n] 在章末参考资料无对应条目 → high |
| 【新】`citation_orphan` | 孤儿条目：章末条目未被正文引用（凑数假装饰）→ medium |
| 【新】`citation_ledger_ref` | 正文 [n] 须在台账 ref 列注册过（注册中心闭环）→ high |

新检查器注册 `CHECKERS` + `CHAPTER_CHECKERS`（进门禁）。`SOURCE_RE`/`ATTRIBUTION_RE`
并立不替换（过渡期）。`tests/report_qa/test_checks.py` 三组测试按新样式改写 + 双样式过渡用例。

### 2.3 金缺陷同步

## 3. 子包 V：核验与审校（双角色，一个独立模型）

**澄清议题①②定稿。**技术通路（调研实证）：`PluginContext.get_model_access` →
`ModelAccess.invoke_text`（system/temperature/timeout_s/`response_format="json"`），不进主对话流。

### 3.1 承重断言核验（章级第五道，merge 前复查靠既有检查器）

- **抽取**：独立核验模型从本章文本抽取承重断言（分类表：上市/并购/实控人/主体名称/关键年份/
  投资额——设计裁量：分类清单形式化进提示词），正则预筛关键词控制召回（上市|并购|收购|股票代码|
  实控人 等），一章预期 3~8 条；
- **核验**：每条断言 → searchfree 检索（多查询冗余，官方源优先）→ 【新工具】`fetch_url_text`
  抓正文（searchfree 只有 snippet，调研实证）→ 模型比对断言 vs 证据；
- **判定三档**（澄清定稿）：证实=通过；证伪=必须删改；查无实证=降级强度+[待核实]；
- **闭环**：判 dirty → 章级门禁阻断开新章 → 作者趁上下文热就地修复 → 复测；
- **额度**：与格式修复共用本章 N=2 总预算（澄清定稿）；
- **留痕**：核验结果（断言/判定/证据 URL）落盘 `verification_log.jsonl`（呼应 A4 精神）；
- **抓取复用既有工具（builder-check 修正）**：正文抓取直接用既有 `web_fetch`
  （带 SSRF 防护、重跟随、5MB 上限、markdownify 转正文），不新造 `fetch_url_text`；
  web_fetch 是同步 httpx，核验工序里以 `asyncio.to_thread` 包装调用，不堵事件循环；
- **核验自身可靠性（fail 策略，设计裁定）**：核验调用走独立通路，patient_retry 管不到，
  需自带超时（默认 120s）+ 有限重试（2 次指数退避）。连续失败 → 记「核验事故」：
  **章级 fail-open**（不阻塞写作，留痕 `verified=pending`），**merge 闸 fail-closed**
  （merge 前补核，仍无法核验则硬失败不放行）——写作期不因端点抖动停摆，成书期不许漏核。
  验收线按核验日志统计「实际核验覆盖率」单列；
- **一般财务数值抽检**：每章随机抽至多 3 条（设计裁量，可配置），走同一通道。

### 3.2 审校链（merge 前文字编辑）

- **触发**：merge 闸发现「存在未审校章」→ harness **自动**跑审校工序（不等模型——设计裁定，
  比「提示模型去审校」可靠），审校改动落盘、章置 dirty、阻断本次 merge 并附言
  「审校已改 N 处，复测后再合并」；
- **审校模型**：同独立模型，只读文本（无检索），返回 `{"edits":[{"line":N,"new":"..."}]}`；
- **编辑约束**：整行替换、每处 ≤300 字、**不设章级处数硬上限**（同事管线 4 处上限实证修不完）；
  审校后字数复检（不得低于下限）；脚本按行号倒序应用（防行号漂移）；
- **留痕**：`review_audit.jsonl`（行号/原文/新文/理由）；
- **事实疑点回流**：审校发现事实疑点不独自判，写入核验队列下轮核验（澄清定稿）；
- **顺序**：先事实核验（章级），后逻辑审校（merge 前）——承重断言是假的，审校全是无用功。

### 3.3 门禁状态机扩展（builder-check 修正后定稿）

- **执行主体：扩展 chapter_gate 本身，不另起插件**（设计裁定）。理由：verified/reviewed 状态
  必须与 clean/dirty 同一状态机共存，拆成独立插件就要跨中间件共享章状态（无现成机制）；
  chapter_gate 在 agent.py:1483 挂载处 `self._model_factory` 现成可用，核验/审校所需的
  `ModelAccess` 在挂载时注入即可。harness 层改动，零内核；
- `_ChapterState` 加 `verified`、`reviewed` 两个维度；merge 闸前置条件升级为
  「全章 clean + verified + reviewed」；repair_rounds 语义不变（核验失败计入 N=2）；
- **失效规则（设计裁定）**：任何 write/edit 章文件 → 同时清 unevaluated/verified/reviewed
  （与既有「编辑即失效」行为一致，宁保守不错放）；**审校工序自身的改动例外**（工序内置豁免标记，
  否则审校改完即自清 reviewed 死循环）；核验成本由「只对含承重断言章触发 + 每章 3~8 条」控制；
- **merge 旁路封堵（builder-check 新发现）**：现有 merge 闸只拦 `merge_chapters` 工具调用，
  模型直接 write/edit `report_merged.md` 可绕过全部成书期工序。本期堵上：对 report_merged.md
  的 write/edit 加拦截，引导走 merge_chapters（无裁量项，硬失败）；
- **独立模型配置入口（设计裁定）**：env `OCTOP_VERIFY_MODEL`（provider/model ref 格式与
  get_model_access 的 spec 一致），缺省回落主模型——不新增配置体系；
- 状态落盘（A4 联动）：`_chapters` 状态随 `gate_release_notes.md` 一起持久化，重启可恢复
  （调研坑①：现状态全内存，重启即丢）。

## 4. 子包 W：模型调用看门狗（A5）

- 新增 `WatchdogMiddleware`：`awrap_model_call` 用 `asyncio.wait_for` 包住调用，
  超时抛可重试异常；**挂载位置钉死：patient_retry 内侧**（每次重试独立计时，
  放外侧会把重试循环打穿——调研结论）；
- **挂法修正（builder-check 发现原设计互斥）**：链序事实是插件中间件链（经
  `PluginRegistry().build_middleware_chain`）落在 chapter_gate **之后**（即内侧），
  插件之间按 priority 排序。所以正确挂法 = **看门狗做成 harness 插件中间件，priority 排在
  meerkat-resilience（patient_retry）之后（内侧）**；「照抄 chapter_gate 挂载模式」作废——
  照抄会把看门狗挂到 patient_retry 外侧，正是设计自己警告的形态；
- **执行计划含核实任务**：「超时抛的异常类型」必须确认能被 patient_retry 的
  `default_retry_on` 判为可重试，否则直接拒收（拔测验证，见执行计划）；
- 默认超时 **300s**（设计裁量：单节 2,000~4,000 字生成的正常耗时上限；env
  `OCTOP_MODEL_WATCHDOG_TIMEOUT_S` 可调）；开关 env `OCTOP_MODEL_WATCHDOG_ENABLED=1`；
- 超时事件记日志 + 计入轮次记录的事故栏（预算口径：挂起恢复不计预算计事故——需求 §5 钉死）。
