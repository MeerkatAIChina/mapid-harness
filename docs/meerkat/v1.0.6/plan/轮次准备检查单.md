## 3. 事故出口约定（fail 策略复诵）

- 核验 infra 失败：章级 fail-open（`verified=pending` 留痕 `verification_log.jsonl`），**不消耗本章 N=2 修复额度**；
- 连续 3 次 infra 失败 = 事故中止：本轮后续章跳过核验，turn 自然结束，轮次记环境事故、作废重跑，不死等；
- merge 闸 fail-closed：未核验/未审校章硬失败不放行（不消耗 merge_rounds）；
- 出口举证核实 infra 失败按驳回处置（fail-closed，出口不虚开）。

**终审修复后新增的门禁语义（2026-11-04，详见 `终审修复记录.md`）：**

- 查无实证未处理（未降级、未标 `[待核实]`）→ merge 硬失败；标注复测后放行；
- 诚实出口只豁免字数下限：核验/审校两道工序对出口章同样强制，审校改文后该章
  `verified` 作废，merge 前自动对改后文本重核；
- 交付验收三格式统一扫描占位符/生成残留（PDF 走 pdftotext 软依赖）；图表契约
  （title/rationale/refs）不过即拒建；merge 新增跨章同号异源与台账重复取号检查；
- 检索 `No results found.` = 查无实证（不消耗额度、不计事故），与 `Error:` 故障分开。

**复验补修追加（同日）**：PDF 提取工具缺失 = 验收失败（fail-closed，装配时须确认
pdftotext 可用——本机已装 Git for Windows 自带版 `D:\Git\mingw64\bin\pdftotext.exe`，
但不一定进所有 shell 的 PATH，装配时逐环境验证 `pdftotext -v` 再跑验收）；引用一致性
双向（同号异源 + 同源异号）；台账反查断言按正文同事实标注出队。
