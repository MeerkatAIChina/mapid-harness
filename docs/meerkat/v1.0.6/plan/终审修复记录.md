## 一、merge 绕过三条（阻断级）

### 1. 审校改完不再核验（commit 217c224）

- **现象**：审校把已核实的年份 2020 改成 2099，第一次 merge 被拦（审校已改），第二次 merge 直接成功，错误值进合并报告。
- **根因**：`apply_review_edit()` 保留旧 `verified`；`_auto_reviewed` 拦一次即清空，第二次无任何阻断依据。
- **修法**：审校改文后 `verified` 清回 `unchecked`（核验结论随文本作废），merge 前补核对改后文本重验。裁定 14 的「编辑即清」豁免只留 `reviewed` 维度。
- **复现测试**：`test_review_edit_forces_reverification`（2099 场景，第二次 merge 必须拦下证伪断言）；反转了两个把错误行为固化成预期的既有测试。

### 2. 字数出口连带豁免核验/审校（commit 9458351）

- **现象**：字数不足章出口举证通过后，`verified=unchecked`、`reviewed=False` 也能合并。
- **根因**：`exit_granted` 是 merge 前补核、自动审校、硬门禁三处的共同跳过条件。
- **修法**：出口豁免收窄到 `_floor_finding` 一处；核验触点与补核的「脏章先修格式」改按内容 findings（剔除字数项），floor-only 章不再绕过核验（否则死锁：永远核不了、永远拦）。
- **复现测试**：`test_exit_granted_does_not_skip_verification`（核验 pending 的出口章 merge 硬失败）。

### 3. 查无实证仍放行（commit 601d0bb）

- **现象**：核验判「查无实证」只进 `verify_notes`，不影响 `verified=passed`，补审校后连续四次 merge 均成功。
- **修法**：merge 硬门禁新增 `verify_notes` 未清零检查；模型按附言指引降级删除或标注 `[待核实]` 后重核出队（已标注的查无实证断言视为已降级处置）。顺带修正：参考资料节文本不再参与承重断言抽取与数值抽检（条目不是断言）。
- **复现测试**：`test_unverifiable_blocks_merge_until_marked`（标注前硬失败、标注后放行）。

## 二、成品验收三条（高优先级）

### 4. 占位符漏检（commit 748a762）

- **现象**：round-4 真实三格式产物有两处「XX 亿千瓦时 / XX 万小时」，交付验收返回空。
- **修法**：HTML 可见文本、DOCX 提取文本、PDF 文本（pdftotext 软依赖）统一扫描 Markdown 残留 + 生成残留禁词 + 占位符（复用 report_qa 同一 `PLACEHOLDER_RE` 口径）。注意 pdftotext 必须按 UTF-8 字节解码——`text=True` 在中文 Windows 走 GBK 会炸 reader 线程。
- **实证**：修复后对 round-4 真实产物复跑，三格式全部 FAIL 占位符项（HTML/Word「XX 亿」、PDF「XX」）。

### 5. 图表校验未接交付链（commit 1103415）

- **现象**：缺 title/rationale/refs 的图表可进三格式构建；heatmap 缺 `heat_data` 能过校验但渲染对空列表求 min/max 崩溃。
- **修法**：`convert()` 渲染前对全部 chart 块跑 `validate_chart`（不过即拒建）；`build_outputs` 发现旁边 `data_ledger.md` 即启用 refs 注册核对；`_validate_structure` 补 heatmap `heat_data` 三元组校验。
- **复现测试**：`test_build_rejects_chart_missing_contract` / `test_build_rejects_chart_refs_not_in_ledger` / `test_heatmap_rejected_without_heat_data`。

### 6. 全书引用编号未闭环（commit 0c39783）

- **现象**：两章都用 `[1]` 分别指向甲、乙两份年报，检查零违规；两个不同指标重复注册 `ref=1`，集合化后冲突不可见。
- **修法**：新增 `citation_cross_chapter`（同号多源文本 → high）与 `ledger_ref_duplicate`（同号多指标 → high），并入 merge 检查器集；`parse_ledger_refs` 拆出行级解析 `parse_ledger_ref_rows` 复用。同指标同号多行属数值冲突，仍归 `numeric_consistency` 管，不重复报。
- **复现测试**：5 个新用例（冲突必中 / 同源合法 / 重复取号必中 / 同指标同号豁免 / 无 ref 列豁免）。

## 三、核验状态一条（高优先级）

### 7. 无检索结果误判系统故障（commit 367ec8d）

- **现象**：searchfree 正常返回 `No results found.`，代码直接 `json.loads` 抛异常，按 infra 故障走重试/pending/事故计数。
- **修法**：`No results found.` 显式映射为空清单，走「查无实证」路径；`Error:` 开头仍走 infra。两类状态不再混用。
- **复现测试**：`test_default_search_no_results_is_empty` / `test_default_search_error_still_infra`。
